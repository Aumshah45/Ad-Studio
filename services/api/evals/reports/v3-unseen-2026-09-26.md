## Environment (read first)
**v3 was generated and evaluated on Linux (x86_64); Apple Vision was unavailable.** Compared with the
frozen ev-0.8 record (`evaluator/FROZEN.md`):

| | Frozen record (macOS, arm64) | v3 here (Linux, x86_64) |
|---|---|---|
| OCR engines | Tesseract 5.5.3 + Apple Vision + VLM read-back | Tesseract **5.3.4** + VLM read-back (**no Apple Vision**) |
| Text FAIL rule | two readers agree | same rule, but the two readers are always Tesseract + read-back |
| Judge | `google:gemini-3.8-flash` | same |
| Thresholds, judge prompts, cache version | ev-0.8 | unchanged (freeze guard test passes) |
| Snapshot keys | arm64 PNG bytes | x86_64 PNG bytes: `data/golden/v3/cache` replays here, not on the Mac |

The 32 images, the 13 repair-probe images and the manifest are committed for a full-ensemble re-score
on the Mac. That re-score needs one step first: the manifest's `reference_sha` values are Linux-normalised,
so the harness's reference check ("normalises to a different reference") stops there, the same
platform-bound key issue as v1/v2 on Linux (docs/stack-lock.md). Pixel-based keys fix both directions.
After that, `make eval-record GOLDEN_VERSION=v3` records the missing (Mac) keys live with Apple Vision.
Tesseract 5.3.4 is known to under-read `»` (docs/stack-lock.md, "CI platform and Linux OCR").

## Live repair path on the real failing drafts
`make golden-repair-probe GOLDEN_VERSION=v3` (new, `backend/golden/repair_probe.py`) runs the production
repair loop (`Orchestrator.loop`: routing table, Flash repairs, per-run budget with the first round already
charged, stall guard, overlay) on each of the 6 non-passing first-round drafts, in probe runs that export
never sees. Results: `data/golden/v3/repair_probe.json`, images in `data/golden/v3/repair_probe/`.

| Draft | Draft verdict | Route | Result | Image spend |
|---|---|---|---|---|
| V05 s0 (NZ) | text fail | `text_in_zone` → Flash repair | **passed** (native) | $0.067 |
| V14 s1 (CH) | context fail | `context` → Flash repair | **passed** (native) | $0.067 |
| V15 s0 (FR) | text fail (‘…’ drawn for «…») | `text_in_zone` → Flash repair | **passed** (native, «…» exact) | $0.067 |
| V09 s1 (KR) | text unverified | overlay (no model call) | **passed** (overlay) | $0 |
| V12 s0 (EG) | text fail (drew `%25`, Western digits) | Flash repair → stalled (SSIM 0.99) → overlay | needs_review (`overlay_verify_failed`) | $0.067 |
| V12 s1 (EG) | text unverified | overlay | needs_review (`overlay_verify_failed`) | $0 |

- **Targeted repairs: 3 of 4 fixed the failing dimension in one Flash call** (text ×2, context ×1).
  Drafts salvaged: 4 of 6. Probe spend $0.317 ($0.268 image, $0.049 judge; the judge spend is not
  per-draft because this probe ran before the run-id binding fix in the same commit).
- **V12's overlay is an evaluator false alarm (the human labelled it pass).** The overlay draws «خصم ٢٥٪» correctly (`repair_probe/V12-s1-1-overlay.png`), but Tesseract
  5.3.4 `ara+eng` reads the Eastern Arabic digits as `0017` / `TOs`, so verification fails. With no
  Apple Vision here there is no second engine to disagree. This is the first item to re-score on the Mac.
  The V12 **draft** fail is genuine: the read-back and Tesseract agree the model drew `%25`.
- The V12 s0 repair output was 99% similar to its draft and the judge failed its product, which it had
  passed on the draft. Same image, flipped verdict: a judge-stability case, not a repair regression.

## Evaluator accuracy on unseen data (human labels)

**Label history (read before the numbers).** The human labelled all 32 images blind in the sheet (no
verdicts shown) and marked every dimension of every image `pass`. The agent then showed the human the
four images where the evaluator had failed text and asked whether the passes were intentional, since the
rubric requires the text to be rendered exactly. The human changed **text → fail on V05-nat (stray quotes
added), V12-nat (Western `%` for `٪`) and V15-nat (‘…’ for «…»)** and kept V12-final (the overlay) as pass.
The revised labels are no longer blind on those three items.

| E-nat (16 first drafts), text | TP | FP | FN | TN | Precision | Recall |
|---|---|---|---|---|---|---|
| Revised labels (committed; rubric-consistent) | 3 | 0 | 0 | 13 | 1.000 | 1.000 |
| Original blind labels (all pass) | 0 | 3 | 0 | 13 | 0.000 | — |

- The three disputed drafts are visibly different from the required copy, so the rubric supports the
  revised labels. The spread between the two rows is the honest uncertainty on v3's text precision.
- **Product, context and composition: not measured by v3.** The human found no failure in any of them on any
  image, and the evaluator failed none on E-nat (16/16 agreement), so there are no positives. Precision and
  recall on those dimensions still come from v1/v2 only.
- Overall pass/fail agreement on E-nat: 16/16, κ 1.000 (on the revised labels).
- **E-final (outside the meta-eval): 1 disagreement, V12-final (the overlay),** which the human passed.
  In the pipeline run the evaluator failed its text (Tesseract read ٢٥ as `0017`). The offline replay marks
  its text `unverified` and **fails its product**: "Judge unsure: logo missing or altered? The embossed
  Rubbermaid logo on the grey lid band is indistinct". An unsure checklist item counts as a fail. So this one
  image is two evaluator false alarms (text, product) that the E-nat meta-eval does not count.
